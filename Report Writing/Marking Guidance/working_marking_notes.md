# Working Marking Notes

Use these notes as a standing drafting checklist for `DissoRn.txt`.

- Knowledge and understanding: connect literature directly to the project topic and avoid generic background.
- Method justification: explain why each method, architecture choice, tool, or algorithm is appropriate, ideally with support from literature, previous work, standards, requirements, or implementation constraints.
- Critical thinking: interpret results and design choices, do not only describe them. Include limitations, conflicting requirements, trade-offs, and what the current evidence cannot prove.
- Wider context: relate implementation and evaluation back to comparable systems, literature, or accepted practice.
- Technical achievement: make the implemented contribution visible through clear architecture, testing, diagnostics, supporting documentation, and objective-linked evidence.
- Evaluation: pair each claim with an evidence type, such as automated tests, diagnostics, behaviour reports, timing/state checks, or user/listening evaluation. Be explicit where only future user evaluation can support a claim.
- Technical writing: keep sections well-structured, concise, cited, and not padded. The handbook explicitly warns that using the full word count is not required and padding can be penalised.
- Professionalism: show project management, individual contribution, limitations, and future work clearly in the later chapters.

Drafting rule: when adding or revising a section, ask which marking criterion it strengthens and cut material that does not support a claim, method justification, evidence trail, or limitation.
